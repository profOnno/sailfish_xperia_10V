# Sailfish OS on Sony Xperia 10 V (Zambezi)

> **Note:** This repository is a community-driven knowledge base and debugging log. It was generated by **DeepSeek (AI Assistant)** based on live debugging sessions with a Sony Xperia 10 V and is intended to help others attempting the same port. **AI-generated content is not authoritative** — treat every claim here as a hypothesis to be verified against the device, not as established fact.

## 📱 About the Project

This project documents the process of installing the **Sailfish OS community port** on the Sony Xperia 10 V (codename **Zambezi**, `holi` / Snapdragon 695).

**Device identity — important:** The physical test unit reports **`ro.product.model = XQ-DC72`** (dual-physical-SIM variant), not the XQ-DC54 / PDX-235 that earlier drafts of this document assumed. This was confirmed from a working LineageOS boot (`[ro.product.model]: [XQ-DC72]`) and corroborated by the `holi-qrdsku1-snd-card` audio card name. Firmware, blob, audio-routing and thermal-config assumptions must be calibrated to **XQ-DC72**, not PDX-235. If you are porting on a different `holi` SKU, re-verify everything in the "Stack" section against your own unit.

The goal of this repository is to:
1. Document the flashing steps (Stock Android 14 → LineageOS 22.2 → Sailfish OS).
2. Provide hardware diagnostics (dmesg logs, HAL listings) from the working LineageOS base.
3. Track the known issues (boot hangs, camera crashes, battery reporting) and potential fixes.

## 🧱 The Stack

- **Sony AOSP 14** (reference base for the device configuration, firmware `68.1.A.2.270` — verify this matches XQ-DC72)
- **LineageOS 22.2** (Android 15 base used for the flashing process)
- **Sony v4b Blobs** (`SW_binaries_for_Xperia_Android_13_5.4_v4b_zambezi.img`) — **installation status unconfirmed, see below**
- **Sailfish OS 5.1**

### ⚠️ Open question: are the v4b blobs actually installed?

After many flash cycles, it is **not currently confirmed** that the v4b blob image was successfully written, or that it survived subsequent flashes. `fastboot` reports success per-partition, but a later flash of `boot`/`vendor_boot`/`super` does not overwrite the blob partitions, so the blobs *should* persist — however this has not been independently verified on this unit.

**How to verify (recommended before any further debugging):**
- Read back the blob partitions and compare against the known-good `v4b` image (e.g. `oem_a`/`oem_b`, or whichever partitions the Sony flash script targets — check the script itself, not memory).
- On a working Android boot, confirm the vendor blob fingerprints are present (e.g. camera stack `camera.qcom.so`, `com.qti.chi.override.so`, and the `libofflinelog.so` presence noted below).
- If in doubt: **re-flash the v4b blobs from a clean state and re-verify** before attributing any failure to Sailfish.

Until this is closed, treat "blobs are installed" as an assumption, not a fact.

## ⚠️ Current Status & Known Issues

The port is **not yet a daily driver**. Based on our testing so far:

- **Boot Hang (blocker)**: The device hangs indefinitely at the Sony logo during the `hybris-boot` handoff. **Root cause not yet determined.** Working hypotheses, in order of likelihood:
  1. dm-verity still enforcing on `vbmeta_system` (only `vbmeta` may have been disabled, not `vbmeta_system`).
  2. `hybris-boot` initramfs `fstab` expecting static `system`/`vendor` partitions instead of the dynamic `super` layout used by LineageOS 22.2.
  3. Mismatched `vendor_boot_a` pairing (GKI vendor ramdisk / dtb not matching the Sailfish `boot_a`).
  4. Kernel/initramfs version mismatch.
  None of these are confirmed. See `TROUBLESHOOTING.md`.
- **Touchscreen**: Works perfectly in LineageOS (`fts_ts`), so the hardware is fine. Whether the Sailfish compositor initializes the display is **unverified** — the boot hang currently prevents reaching that stage.
- **Camera**: Expected to crash-loop. **Earlier drafts claimed missing `libofflinelog.so`; this is now known to be inaccurate** — the blob *is present* in the working LineageOS `/vendor/lib64/` (≈51 KB). If Sailfish's camera crashes, the likely cause is that the Sailfish vendor image does not ship the file, or the `hybris` linker namespace does not expose it. Verify against the baseline before assuming.
- **Battery**: Battery indicator may fluctuate. On the LineageOS baseline, SOC tracked correctly (98→100 over 2.5 h); the observable symptom is `smblib_set_icl_current` re-asserting ICL every ~5 s while charging. **This looks cosmetic** (ICL re-negotiation loop), not a gauge fault. Not a blocker.
- **Fastboot**: Sony's bootloader blocks `fastboot boot`. You must flash `hybris-boot.img` to `boot_a`. Sony's fastboot is sensitive to tool version; use v33/v34.

## 🛠️ Hardware Diagnostics

Extensive logs were captured from a **working LineageOS 22.2** boot on the XQ-DC72 test unit as a baseline:

- **HAL Libraries**: `vendor/lib64/hw/` (including `gralloc.default.so`, `vulkan.adreno.so`, the full `camera.qcom.so` stack).
- **Kernel Modules**: `focaltech_fts` (touchscreen), `aw882xx_dlkm` (audio), `camera`.
- **Input Devices**: FocalTech touchscreen (`fts_ts`), Egis fingerprint (`egis_fp`), plus the `holi-qrdsku1-snd-card` audio jack devices.
- **Partition map**: dynamic `super -> sda74`; separate `vendor_boot_a/b`, `dtbo_a/b`, `vbmeta_a/b`, **`vbmeta_system_a/b`** (note: both must be disabled for verity-off testing, not just `vbmeta`).

This baseline is the reference for comparing against the Sailfish kernel logs and initramfs expectations.
